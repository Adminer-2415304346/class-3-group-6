## 1. 模块概况

`accounts` 是项目的账号域 App，承担六类职责：

1. 定义全局用户模型 `BlogUser`（`AUTH_USER_MODEL='accounts.BlogUser'`）。
2. 提供“用户名或邮箱”二合一的认证后端 `EmailOrUsernameModelBackend`。
3. 注册、邮箱激活与注册结果页。
4. 登录、登出、session 有效期与 `logged_user` 前端标记。
5. 找回密码：申请验证码、校验验证码、重置密码。
6. 用户后台的新增/修改表单。

路由与命名空间：

| 路由名 | URL | 入口 | 说明 |
|---|---|---|---|
| `account:login` | `/login/` | `LoginView` | 项目 `include(..., namespace='account')` 的实例命名空间 |
| `accounts:login` | 同上 | 同上 | `app_name='accounts'` 的应用命名空间；两种反查均可用 |
| `account:register` | `/register/` | `RegisterView` | 注册后写入未激活用户 |
| `account:logout` | `/logout/` | `LogoutView` | 清除 session 与 `logged_user` |
| `account:result` | `/account/result.html` | `account_result` | `type=register` 展示成功；`type=validation` 校验签名并激活 |
| `account:forget_password` | `/forget_password/` | `ForgetPasswordView` | 邮箱 + 验证码 + 两次新密码 |
| `account:forget_password_code` | `/forget_password_code/` | `ForgetPasswordEmailCode` | POST 申请验证码，返回纯文本 |

跨 App 边界：

- `djangoblog/base_views.py`：`SecureFormView`、`LoginFormView`、`LogoutRedirectView` 提供 CSRF 装饰与通用行为。
- `djangoblog/utils.py`：`get_sha256`、`generate_code`、`send_email`、`get_current_site`、`delete_sidebar_cache`。
- `djangoblog/blog_signals.py`：`send_email_signal` 负责真实投递；全局 `post_save` 接收器对所有带 `get_full_url()` 的实例做搜索引擎通知。
- `oauth/views.py`：通过 `OAuthUser.author` 外键关联本站用户，但登录时不经过 `authenticate()`。

## 3. 三条源码调用路线（当前分支实测）

### 3.1 注册与激活

`urls.py:account:register` → `RegisterView.form_valid`（`views.py:48`）：

1. `FormView` 先调用 `RegisterForm.is_valid()`：`clean_email` 查重、`UserCreationForm` 校验两次密码与强度。
2. `form.save(False)` 由 `UserCreationForm` 完成 `set_password`（PBKDF2 哈希），拿到未落库实例。
3. 显式 `is_active=False`、`source='Register'`，再 `save(True)`。
4. `get_current_site().domain` 取站点；`settings.DEBUG=True` 时强制覆盖为 `127.0.0.1:8000`（生产必须关闭 DEBUG）。
5. 签名：`get_sha256(get_sha256(SECRET_KEY + str(user.id)))`，即对 `id` 做双重 HMAC-SHA256。
6. 通过 `send_email` 信号同步投递验证邮件，然后重定向 `reverse('accounts:result') + '?type=register&id=...'`。

激活：邮件链接 `type=validation&id=...&sign=...` → `account_result`（`views.py:194`）：

- 先 `get_object_or_404`，无效 `id` 直接 404。
- 已激活用户直接回首页，链接幂等。
- `sign` 与重算值不一致 → 403。
- 一致则 `is_active=True; user.save()`。**该链接没有过期时间**，只要未激活就一直有效。

失败分支：重复邮箱 → 表单错误；邮件发送异常 → 用户已落库但拿不到链接，接口 500，没有补偿重发入口；非法签名 → 403。

### 3.2 登录与会话

`urls.py:account:login` → `LoginForm`（GET 只换控件样式）→ POST 时 `FormView` 先用 `LoginForm.is_valid()` 调用认证后端；`form_valid`（`views.py:142`）又**重新构造** `AuthenticationForm` 再认证一次：

- `EmailOrUsernameModelBackend.authenticate`（`user_login_backend.py:18`）：
  - `username=None` 时从 `kwargs` 取 `USERNAME_FIELD`；仍为空或密码为空 → `None`。
  - 含 `@` 查 `email`，否则查 `username`。
  - `check_password(password) and user_can_authenticate(user)`（改进后包含 `is_active`）。
- `auth.login` 写入 session（循环 session key），`set_expiry` 按“记住我”取 30 天或默认 2 周。
- `logged_user=true` cookie 设置 `httponly=False`，供前端 JS 读取；它不是认证凭证，伪造它不能获得权限。
- 登出：`logout()` 清 session → `delete_sidebar_cache()` → 删除 `logged_user`。

### 3.3 密码恢复

申请：`ForgetPasswordEmailCode.post`（`views.py:260`）→ `ForgetPasswordCodeForm` 只校验邮箱格式 → `generate_code()` → `send_verify_email()` 同步发信 → `set_code()` 写缓存 300 秒 → 返回 `"ok"`。

重置：`ForgetPasswordForm` 字段顺序为 `new_password1 → new_password2 → email → code`：

1. `clean_new_password2`：两次密码一致 + `password_validation.validate_password`。
2. `clean_email`：确认邮箱已注册（会暴露邮箱是否存在）。
3. `clean_code`：`utils.verify` **只读**比较缓存码；失败返回“验证码错误”。
4. `ForgetPasswordView.form_valid`（`views.py:243`）：`make_password` 生成新哈希 → `save()` → **改进后** `delete_code(email)` → 302 到 `/login/`。

生命周期：重复申请会覆盖旧码；TTL 300 秒；改进后成功后立即消费，不能在同一窗口内重放。**没有发送频率限制**，任意格式合法的邮箱都能触发邮件。
