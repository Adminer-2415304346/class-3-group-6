# GZX oauth 质量分析片段

- 主责 app：`src/DjangoBlog/oauth/`；基线提交 `1351db9`；分支 `gzx_branch`。
- 关联证据（不计为本 app）：`accounts/models.py`（BlogUser）、`djangoblog/utils.py`（cache_decorator/get_sha256/send_email/get_current_site）、`djangoblog/blog_signals.py`（oauth_user_login_signal、send_email_signal）、`templates/oauth/*`。

## 1. app 边界

- 负责：发起第三方授权、code 换 token、拉取第三方用户信息、与本站 BlogUser 关联、登录、无邮箱时补邮箱与邮件确认。
- 不负责：本站密码登录（accounts）、邮件真正投递（djangoblog.blog_signals.send_email_signal）、头像下载落盘（信号 oauth_user_login_signal_handler）。
- 上游：模板标签 `load_oauth_applications`、第三方平台回调；下游：`oauthmanager` 渠道适配、`OAuthUser/OAuthConfig` 模型、`djangoblog` 邮件与信号。

## 2. 三条真实调用路线

### 路线一：发起授权（浏览器跳转，非服务端 HTTP）
`templatetags/oauth_tags.load_oauth_applications` → `oauthmanager.get_oauth_apps()`（筛选 `is_enable=True`，缓存100分钟）→ 模板渲染授权链接 → `views.oauthlogin?type=xxx&next_url=...` → `get_manager_by_type(type)` → `manager.get_authorization_url(nexturl)` → 302 跳第三方。
- `type` 来自 GET；`next_url` 先由模板带当前路径，最终在 `get_redirecturl` 用 `url_has_allowed_host_and_scheme` 做同域白名单校验，非法回退 `/`。
- 此路线不接触 token，纯拼接跳转地址。

### 路线二：授权回调（code 换 token → 关联 → 登录）
`views.authorize?type=xxx&code=...` → `manager.get_access_token_by_code(code)`（失败抛 OAuthAccessTokenException 或 broad 异常置 None）→ `manager.get_oauth_userinfo()` → 按 `(type, openid)` `OAuthUser.objects.get`，命中则刷新头像/元数据/昵称复用，未命中保留临时对象：
- **有邮箱**：`transaction.atomic` 内按 email `get_or_create` BlogUser，新用户昵称冲突改用时间戳用户名，挂 `user.author`、保存，发 `oauth_user_login_signal`，`login`，写 `logged_user` cookie，跳 `nexturl`。
- **无邮箱**：先 `user.save()` 暂存，302 跳 `requireemail/<id>.html`。
- **token 失败**：OAuthAccessTokenException 记 warning 回首页；其他异常记 error 后重新发起授权。

### 路线三：补邮箱 → 邮件确认
`RequireEmailView.form_valid`：写 `oauthuser.email` → 生成 HMAC 签名链接 `emailconfirm/<id>/<sign>` → `send_email`（实际由 blog_signals 发信）→ 跳 bindsuccess?type=email。`emailconfirm` 校验签名 → 事务内取/建 BlogUser 并挂载 → login → 发绑定成功邮件 → 跳 bindsuccess?type=success。

## 3. 正面技能（可作为团队范例）

1. **渠道抽象复用**：`BaseOauthManager` 抽象出 `get_authorization_url/get_access_token_by_code/get_oauth_userinfo/get_picture` 三步骨架，五个渠道子类只填 URL 常量与字段映射，views 面向抽象编程（oauthmanager.py:29-60）。
2. **同域重定向校验**：`get_redirecturl` 用 `url_has_allowed_host_and_scheme` 白名单校验 next_url，防开放重定向（views.py:33-45）。
3. **事务绑定**：有邮箱登录与邮件确认都在 `transaction.atomic` 内完成取/建用户与挂载，避免半绑定（views.py:110-127、174-179）。
4. **GitHub 私有邮箱兜底**：公开资料无邮箱时二次请求 `/user/emails`，优先 primary+verified，失败仅告警不中断（oauthmanager.py:329-348）。

## 5. 本轮已做改进

**HTTP 请求显式超时（R1）**：在 oauthmanager.py 增加模块常量 `OAUTH_HTTP_TIMEOUT=10`，基类 `do_get/do_post` 与 `ProxyManagerMixin.do_get/do_post` 四处 requests 调用统一传 `timeout=`。
- 改动前：平台无响应时请求无上限挂起（Bandit B113×4）。
- 改动后：10 秒超时，`requests.exceptions.Timeout` 由上层 try/except 兜底走失败分支；Bandit B113 由 4 降为 0。
- 验证：新增 `OauthHttpRequestTimeoutTest` 两个用例，mock requests 断言 get/post 均带 timeout；隔离跑 `oauth.test_oauth_business_logic` 26 个测试全过（ISOLATED_TEST_FAILURES=0）。详见《工具与验证记录.md》。

## 7. 可复用 Python 规范建议（供团队规范汇总）

1. **外部 HTTP 调用必须显式 timeout**：`requests.get/post(..., timeout=(连接,读取) 或秒数)`，避免单点无响应拖垮工作线程；超时常量集中定义，便于统一调整。
2. **不要用 broad `except Exception: return None` 吞错**：至少 `logger.exception` 保留堆栈，或细分 `requests.Timeout`/`json.JSONDecodeError`/`KeyError`，否则线上失败不可观测。
3. **字典取值优先 `.get()` 并给默认值**：外部平台字段结构不稳定，`datas['email']` 改 `datas.get('email')`，避免缺键 KeyError 被误吞。
4. **隐藏字段不是鉴权**：表单 hidden 携带的 id 可篡改，涉及归属/权限必须在服务端用会话或签名校验，不能把隐藏值当凭证。
