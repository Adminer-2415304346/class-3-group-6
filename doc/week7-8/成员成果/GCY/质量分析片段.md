## 1. 核对后的调用链

列表查询：`ArticleListView/OptimizedArticleQueryMixin → CachedListViewMixin → 数据查询缓存`。
文章保存：`Article.save → post_save → model_post_save_callback → _invalidate_article_caches`，清首页、评论键、分类/标签/作者/归档及侧栏/seo等当前实现的键。
该通用回调不监听Article.post_delete，不能把普通删除写成同一条链；裸QuerySet.update也不触发post_save。

评论写入：`Comment.save → pre_save保存旧article_id → post_save.comment_saved → invalidate_comment_caches → transaction.on_commit`。
评论删除：普通/后台/文章或用户级联删除实际涉及的每个Comment分别发`post_delete → comment_deleted → on_commit失效`，覆盖多层、跨文章后代。
后台批量启停：锁定并固定主键后update，动作显式调用失效入口；不逐条save，不补发通知。

普通公开评论通知：`comment_saved → transaction.on_commit → _send_committed_comment_email → _thread.start_new_thread(send_comment_email) → comments.utils.send_comment_email → djangoblog.utils.send_email → send_email_signal → send_email_signal_handler → EmailMultiAlternatives.send + EmailSendLog`。
邮件信号处理器在调用它的线程同步执行；异步点在启动评论通知线程处。回滚不启动，提交时已删除/禁用则跳过，不保证真实投递。

## 2. 风格、设计与技能观察

- G1显式导入使后台注册来源可追踪；G3删除未用符号，未改Whoosh检索算法。
- 缓存装饰器支持普通函数与带自定义键的方法。可选方法缺失走参数repr回退；方法本身出错向上传播，无参调用不访问空args。
- 哨兵仅区分返回None与未命中；并非所有空结果都已统一缓存。参数repr不要求可哈希，含地址时不保证跨进程键稳定。
- get_blog_setting按固定键缓存模型对象；cache.set未传timeout，使用后端默认值，默认LocMem TIMEOUT=10800秒。它与seo_processor是两个键，不能声称删除后者即清掉前者。
- 插件注册与执行分离；异常回调即使没有__name__也不会因记录日志再抛错，后续Action/Filter继续执行。
- 外部推送显式timeout=5；权限异常挂载正确handler403并返回真实403页。找回密码验证码已使用secrets，而不是将random.sample解释为普通非敏感场景。
- HTML日志链接落点保留escape + reverse构造，mark_safe本身不是净化。现有B308/B703作为已核对误报记录；新落点仍需审查。

## 5. 可供全组编码规范采用的建议

1. 多种调用形态先显式分支，再处理缺省；不要为消除bare except而漏掉原调用契约，真实异常不能当缓存MISS吞掉。
2. 共享缓存写入口明确键、事务时机、批量与完整级联路径；回滚不删相关缓存，无关验证码等状态保留。
3. 外呼明确超时与失败日志；验证码等安全敏感随机值使用secrets，先查真实业务用途再分流安全告警。
4. 固定扫描版本、配置、cwd、生产/测试范围及源码指纹；个人材料与自动化集成证据分别注明执行者，不代签本人复核。

以上为已验证实例支持的建议，不冒充全组已确认决议或正式Word交付。
