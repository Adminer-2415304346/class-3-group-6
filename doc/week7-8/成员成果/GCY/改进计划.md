## 已完成改进

### G1：`admin_site.py` 星号导入 → 显式导入（消除 Ruff F403×9 + F405×24）
- **原因**：9 个 `from xxx import *` 造成命名空间污染、静态分析不可追溯，且是本模块最大告警来源。
- **改动**：改为逐模块显式导入；注册代码（`admin_site.register(...)`）未动。
- **符号来源核实**（改动前逐一确认，避免漏导入）：
  - `accounts.admin` → `BlogUserAdmin`；`accounts.models` → `BlogUser`
  - `blog.admin` → `ArticlelAdmin, BlogSettingsAdmin, CategoryAdmin, LinksAdmin, SideBarAdmin, TagAdmin`
  - `blog.models` → `Article, BlogSettings, Category, Links, SideBar, Tag`
  - `comments.admin` → `CommentAdmin`；`comments.models` → `Comment`
  - `oauth.admin` → `OAuthConfigAdmin, OAuthUserAdmin`；`oauth.models` → `OAuthConfig, OAuthUser`
  - `servermanager.admin` → `CommandsAdmin, EmailSendLogAdmin`；`servermanager.models` → `EmailSendLog, commands`
- **影响**：行为等价（显式导入为原星号导入的等价子集）；后续新增模型/Admin 需显式补充（注释中已注明）。

### G2：`utils.py` 裸 `except:` → `except (AttributeError, TypeError)`（消除 Ruff E722）
- **原因**：裸 except 会吞掉缓存实现自身的真实异常，掩盖缺陷。
- **改动**：仅当视图对象缺少 `get_cache_key` 属性（AttributeError）或调用方式错误（TypeError）时走降级键，其余异常正常抛出。
- **影响**：正常路径（视图带 get_cache_key / 不带）行为不变；异常面收窄，更易暴露问题。

### G3：`whoosh_cn_backend.py` 删除未使用导入与变量（消除 Ruff F401×3 + F841×2）
- **原因**：`StemmingAnalyzer`、`ContextFragmenter`、`whoosh_highlight` 三个导入未使用；`model_klass`、`ca` 两个局部变量赋值后未使用。
- **改动**：删除上述符号；`HtmlFormatter` 因 `WhooshHtmlFormatter` 继承依赖而保留（注释中已注明）。
- **影响**：仅删除死代码，行为不变；`ChineseAnalyzer` 等仍在使用。

### G4：`spider_notify.py` `requests.post` 增加 `timeout=5`（消除 Bandit B113）
- **原因**：百度推送接口无响应时，无超时请求会阻塞请求线程。
- **改动**：`requests.post(settings.BAIDU_NOTIFY_URL, data=data, timeout=5)`。
- **影响**：推送失败 5 秒内返回并由原有 except 记录日志，主流程不受影响（尽力而为语义不变）。

### G5：`urls.py` `handle403` → `handler403`（修正笔误，人工问题 P-01）
- **原因**：Django 约定模块属性为 `handler403`，原 `handle403` 不被识别，`permission_denied_view` 从未挂载。
- **改动**：重命名为 `handler403`，错误处理字符串 `'blog.views.permission_denied_view'` 不变。
- **影响**：403 时改走自定义错误页（`blog/error_page.html`，status=403）；`handler404/handler500` 保持不动。
