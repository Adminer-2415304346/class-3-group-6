## 2. S91 固定动作允许列表

### 核实结果

| 核查项 | SY 报告 | 实际核实 |
| --- | --- | --- |
| 动作注册表 | 只注册 `python_version`，参数代码固定 | `CommandHandler.ACTIONS = {"python_version": (sys.executable, "--version")}`，数据库只存动作 ID，参数不由消息或库内文本拼接 |
| 执行方式 | `shell=False`，固定 argv | `subprocess.run(list(ACTIONS[...]), shell=False, capture_output=True, text=True, errors="replace", timeout=..., check=False)`，argv 为列表，无 shell 解释 |
| 动作二次控制 | 受 `ROBOT_ALLOWED_ACTIONS` 控制 | `resolve` 先校验动作在注册表内，再比对 `ROBOT_ALLOWED_ACTIONS`；未启用返回“此动作未启用”，执行器不被调用 |
| 旧 shell 文本 | 明确拒绝并提示迁移 | `command.command not in self.ACTIONS` 返回“旧命令配置已停用，请在后台填写固定动作 ID python_version”；测试 `test_legacy_action_never_reaches_process` 断言 `subprocess.run` 未调用 |
| 后台校验 | 动作 ID 限制在注册表内 | `CommandForm.clean_command` 非注册表 ID 直接 `ValidationError`；测试 `test_help_excludes_legacy_and_admin_validates_new_actions` 覆盖合法/非法两条表单 |
| 超时 | 默认 10 秒 | `ROBOT_COMMAND_TIMEOUT_SECONDS` 默认 10；`subprocess.run(timeout=...)`，捕获 `TimeoutExpired` 返回“命令执行超时” |
| 输出上限 | 默认 4096 字符 | `ROBOT_OUTPUT_MAX_CHARS` 默认 4096；`_limit_output` 超长截断并补省略号，测试用 12 字符阈值断言截断结果 |
| 非零退出 | 明确失败提示 | `returncode != 0` 返回“命令执行失败（退出码 N）”，不回显命令拼接内容 |
| 帮助 | 只列可执行项 | `get_help` 仅保留 `command in allowed and command in self.ACTIONS` 的记录；停用/旧配置不出现 |
| 未知标题 | 拒绝 | `title` 非字符串或长度 >300、按 `title__iexact` 未命中均返回未找到提示，不触达进程 |

### 发现

- 注册表、后台表单、`resolve`、`get_help` 四处口径一致：动作必须同时在代码注册表与启用列表内才可执行。
- 执行 argv 完全来自 `ACTIONS` 常量，`run` 仅用标题解析出动作 ID，聊天消息与数据库文字都不会进入命令行参数，shell 注入面已收敛。
- 动作新增需改代码注册表并在维护配置登记启用，当前为单点白名单设计，方向符合任务单“不能让聊天消息或数据库文字变成任意参数/批处理”的要求。

### 结论

**S91 实现真实、行为与任务单一致**，固定 argv、`shell=False`、超时与截断均可复现，可进入集成。

## 3. S92 管理员期限与命令确认票据

### 核实结果

| 核查项 | SY 报告 | 实际核实 |
| --- | --- | --- |
| 会话隔离 | 按发送者隔离 | `owner = get_sha256("week910:servermanager:owner:" + userid)`，DB 会话按 owner 主键隔离，标识只存摘要 |
| 会话期限 | 认证有效 900 秒 | `ROBOT_SESSION_TTL_SECONDS` 默认 900；`_active_session` 附加 `expires_at__gt=now` 条件，过期会话取不到记录 |
| 票据期限 | 命令确认 60 秒 | `ROBOT_CONFIRM_TTL_SECONDS` 默认 60；`ticket_expires_at = min(grant.expires_at, created_at + 60s)`，票据不晚于会话到期 |
| 票据绑定 | 绑定用户、会话、标题、动作、消费状态 | 记录含 `session_id`、`ticket_title`、`ticket_action`、`ticket_created_at`、`ticket_expires_at`、`ticket_consumed`；消费时 `expected_action` 与票据动作二次比对 |
| 一次消费 | 持久化条件更新，仅一个请求取得资格 | `_consume_ticket` 用 `filter(owner, session_id, ticket_id, ticket_expires_at__gt=now, ticket_consumed=False).update(ticket_consumed=True)`，返回值非 1 即拒绝；先条件更新成功才调用 `cmd_handler.run` |
| 退出/重认证 | 旧票据不可复活 | `EXIT` 与重新 `ADMIN` 均走 `_reset_session(revoke=True)` 删除 DB 会话；测试 `test_logout_and_reauthentication_invalidate_previous_ticket` 用退出前、重认证前两份旧会话快照确认旧 Y 被拒、执行器 0 次 |
| 发送者归属 | 不同发送者不能领取同票据 | `_active_session` 按 owner 过滤；测试 `test_confirmation_is_scoped_to_its_sender` 以另一发送者复用同一票据，返回“过期”且执行器未调用 |
| 失败/过期/重放 | 执行器次数为 0 | 票据过期、会话过期、旧快照重放分支均在调用 `cmd_handler.run` 前返回；对应测试以 mock 断言 `execute.assert_not_called()` |
| 三次失败 | 连续三次口令错误结束认证 | `Count >= 3` 调用 `_reset_session()`，返回“超过验证次数”；测试 `test_third_wrong_password_ends_attempt` 覆盖 |
| 旧会话兼容 | 旧状态不能因缺期限字段保留权限 | `WxUserInfo.from_payload` 对字段集合、布尔/整数/字符串类型、范围与一致性做严格校验；缺 `SessionId`/票据等字段的旧 JSON 解析为未认证，测试 `test_old_json_without_current_grant_is_not_authenticated` 覆盖 |
| 状态载体 | 有界纯 JSON | 会话只序列化 `WxUserInfo.FIELDS` 标量；权限与票据状态以数据库为准，不反序列化对象标签 |

### 发现

- 票据消费以数据库条件更新为准，会话侧 JSON 仅作辅助；跨请求/跨进程下“只成功一次”的判断落在 DB 条件更新上，方向正确。
- 票据到期取会话到期与票据 TTL 的较小值，避免会话已过期而票据仍可执行的窗口。
- 口令校验为双重 SHA256 + `compare_digest` 常量比较；测试通过 `override_settings` 注入临时口令摘要，代码与测试未提交真实口令。

### 结论

**S92 实现真实、行为与任务单一致**，期限隔离、票据绑定、一次消费与撤销路径均可复现，可进入集成。

### 5.2 【建议 · P3】并发一次消费尚缺生产库与真实链路复测

- S-T08 在本地 SQLite（内存/磁盘）下用两份会话副本验证只执行一次；`接手验证.json` 已声明尚无生产 MySQL 与真实微信联调记录。
- DB 条件更新方向正确，但多实例部署、共享数据库连接池与真实微信回调时序下的行为仍建议在生产配置环境复测一次。

### 5.3 【建议 · P3】既有测试 patch 粒度不统一

- `tests.py::test_configured_action_runs` patch 的是全局 `subprocess.run`，而 `test_week910_functional.py` patch 的是模块级 `servermanager.api.commonapi.subprocess.run`。
- 建议统一为模块级 patch，避免全局替身跨用例残留；当前不影响本轮结论。

### 5.4 【建议 · P3】WeRoBot token 仍有硬编码兜底

- `robot.py:34` 在环境变量缺失时回退到默认 token `"lylinux"`，属第7—8周遗留，非本轮改动。
- 建议生产环境强制从环境变量读取，缺失时启动报错，避免默认弱口令上线。

### 5.5 【建议 · P3】口令哈希无独立 salt

- 口令为双重 SHA256 比较，无独立 salt；既有逻辑，当前测试与部署风险低。后续可迭代为带 salt 的慢哈希（PBKDF2/Argon2）。

### 5.6 【建议 · P3】过期会话与票据缺少全局清理

- `RobotAdminSession` 仅在退出、重认证或发起新票据时被覆盖/删除，无按 `expires_at` 的批量清理任务；当前数据量小，不影响功能。可在后续维护任务中过期清理，与其他 App 的过期状态记录一并处理。

### 5.7 【建议 · P3】功能测试驱动方式与任务单字面口径不同

- 任务单 §2 写“使用 Django Client 验证 HTTP/表单/数据库结果”，实际功能测试以本地消息对象直接调用 `MessageHandler` 配合 `override_settings` 驱动，未走 Django Client/HTTP 层。
- 功能边界覆盖到位（见 4.3），建议后续补充 HTTP 层用例，或在实现说明中注明实际驱动方式。

## 6. 跨模块边界检查

- **公开文章入口**：`recent/category/search` 沿用 `BlogApi`，渲染前二次过滤 `status="p"` 且 `type="a"`，草稿、页面与陈旧索引对象不出现（S-T01 覆盖）；本轮未改动 blog 文章可见性规则。
- **会话存储回退**：缓存不可用时回退 `FileStorage`，且探测/回退过程不删除已有会话数据（S-T09 覆盖）；不依赖特定缓存后端。
- **邮件日志边界**：`EmailSendLog` 只记录投递结果，后台只读、不可新增；共享邮件投递链路不在本模块职责内，本轮未改动。
- **配置入口**：机器人相关阈值与允许动作统一走 `get_maintenance_option`，与 accounts/oauth/comments 的维护配置入口一致；未知键、非正数、重复/非法取值均会被校验拒绝。
- **敏感标识**：owner 键为 `week910:servermanager:owner:<摘要>`，用户标识只写 SHA256 摘要，不明文进入缓存键与日志；日志仅记录异常类别，不记录口令、提示词或服务响应。
- **与其他 App 状态隔离**：本模块不写入 oauth 绑定状态、accounts 验证码状态或 comments 发布状态；各 App 缓存键前缀与签名盐互不复用。
