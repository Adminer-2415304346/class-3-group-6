## 4. 边界与证据核对

- **阈值来源**：长度、间隔、重复窗口均经 `get_maintenance_option` 读取，comments 内未硬编码默认阈值；模型 `body.max_length=2000` 仅作硬边界，表单按配置值校验。
- **状态记录实现**：限频/重复状态落在本 App `CommentPostState` 表，唯一约束 `(user, scope, state_key)` 承担并发互斥；`state_key` 存 SHA-256 摘要，不落正文/文章明文。文档未把缓存后端描述成跨进程原子，口径与实现一致。
- **事务一致性**：状态预留与评论写入同一事务；回滚时状态行一并撤销，不残留“成功冷却”，也不触发提交后的缓存失效与邮件通知。
- **既有回归**：`comments/tests.py` 仅新增 `expire_post_state()` 辅助方法并在两处连续提交前清空状态，import 补 `CommentPostState`，既有断言未改动；其余既有 comments 用例随标签集一并复跑通过。
- **证据链**：`after-tests.json` 汇总（90/0/0/0）与 `after-tests.log` 末行 `Ran 90 tests`、`ISOLATED_TEST_FAILURES=0` 一致；baseline 包装器 60/0，原始 raw 60/7（compressor 在 Windows 下子进程探测所致）如实保留，未掩盖；扫描 manifest 的文件清单、工具版本、命令口径与复跑结果一致。
- **代码统计**：`代码变更统计.md` 按 `git diff --numstat` 区分新增/删除/原地替换，未把新增行等同修改行；与 `0ba81a9^..6be622e` 的 diff 行数基本吻合。
