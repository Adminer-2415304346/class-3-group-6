## 1. 现象与目标

7—8 周已完成 HTTP 超时、三层注释与质量报告。本轮按任务单完成两个必做项：

- **O91**：OAuth state 绑定会话并按期一次消费。原 `oauthlogin` 不生成 state，`authorize` 直接拿 code 换 token，存在 CSRF、重放、跨浏览器回调风险。
- **O92**：邮箱归属、绑定期限与一次确认。原 `RequireEmailView` 用无时效 HMAC(id) 签名，`emailconfirm` 不校验邮箱归属、不防重放，同邮箱已有本地账号时静默 `get_or_create` 导致账号归属混淆。

选做 O93（后台/日志敏感数据最小化）本轮未实施，列入后续计划。

## 3. 关键设计

### O91 state 会话绑定

- `oauthlogin` 用 `secrets.token_hex(32)` 生成 state，按渠道存 `request.session['oauth_states'][type]`：`{state, created_at, next_url}`。
- `get_maintenance_option('OAUTH_STATE_TTL_SECONDS')` 读 300 秒 TTL。
- `authorize` 回调：从 session 取该渠道记录，`secrets.compare_digest` 比对、时间窗检查；任一失败返回 403 且**不调用** `get_access_token_by_code`。
- 验证通过后立即 `states.pop(type)` 消费 state；next_url 以会话中已校验值为准，不再信任回调 query。
- 同渠道再次发起会覆盖旧 state，旧回调自然失效。

### O92 一次性邮箱绑定

- 新增 `PendingBinding`：nonce 唯一、`consumed` 布尔、`expires_at` 由 `OAUTH_BIND_TTL_SECONDS`（600 秒）控制。
- `RequireEmailView.form_valid` 和 `_start_pending_binding` 创建记录时同时种入 `browser_context = secrets.token_hex(16)` 到 session。
- 签名用 `TimestampSigner(salt='week910.oauth.bind')` 签 `oauthuser_id:email:nonce`，`unsign(max_age=600)` 做时间窗校验。
- `emailconfirm` 顺序：验签名 → 查 PendingBinding → 校验归属/未消费/未过期 → 校验 browser_context 同浏览器 → 校验同邮箱已有账号时当前登录者就是该账号 → **最后** `filter(nonce=nonce, consumed=False).update(consumed=True)` 条件消费。
- 同邮箱已有本地账号且未登录 → 403 提示先登录；登录后确认 → 绑定到该账号。新邮箱 → 创建本地用户并绑定。
- 已绑定但 `is_active=False` 的 author 直接 403，不建立登录态。

## 4. 复现与交接

**测试运行**（在仓库根）：

```powershell
# 基线
python doc/week7-8/tools/run_isolated_tests.py oauth.test_oauth_business_logic djangoblog.test_week910_configuration
# 本轮 after
python doc/week7-8/tools/run_isolated_tests.py oauth.test_oauth_business_logic oauth.test_week910_functional djangoblog.test_week910_configuration
```

- 隔离 runner 已用 SQLite 内存库、LocMem 缓存/邮箱、SimpleEngine，并阻断网络；所有第三方平台调用在测试中用 `MagicMock` 替换。

- 浏览器上下文：测试用同一 Django test client 保持 session；换 client 即模拟换浏览器，预期 403。

## 6. 石兆翔接手后的实现与复现

顾梓鑫的首轮实现 `b718115` 和后续修复 `147d105` 均纳入当前版本。石兆翔在此基础上完成 `dd99a32`，补齐 O91、O92 的验收边界。

- O91 先校验渠道、浏览器会话、期限和 state，再由 `OAuthLoginState` 条件更新一次消费。旧回调被拒绝时，新 state 仍可使用。五个渠道继续使用后台配置的 callback，回跳地址使用发起授权时保存的站内地址。
- O92 对所有待绑定邮箱发确认信。新邮箱验证后才创建本地账号，已有同邮箱账号由当前登录且已激活的账号显式确认。证明、账号创建及关联在同一事务内。取消或重发会作废原证明。仍有效的旧限时签名可确认，旧无限期签名已失效。
- 升级时应用 `oauth/0005_oauth_login_state`。新增表保存每个浏览器和渠道的最新 state，待绑定表沿用已有记录。回调错误日志只保留渠道、状态或异常类型。O93 的后台密钥显示调整仍待实施。
