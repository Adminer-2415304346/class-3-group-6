# GZX 第9—10周 oauth 功能测试记录

**环境**：Python 3.12.3、Django 5.2.17、隔离 runner（SQLite 内存/LocMem/SimpleEngine，网络阻断）
**结果**：48 项全部通过（oauth.test_oauth_business_logic 34 项 + oauth.test_week910_functional 13 项 + djangoblog.test_week910_configuration 10 项，去重后共 48）。

## 逐项验收

| 编号 | 场景 | 结果 |
| --- | --- | --- |
| O-T01 | 每个已启用渠道发起授权，URL 含 state 且 callback 保持配置值 | 通过：`oauthlogin` 返回 302，Location 含 `state=`，session 按渠道存 state/created_at/next_url |
| O-T02 | 合法同浏览器回调换 token 一次并登录 | 通过：`get_access_token_by_code` 仅调一次，state 被消费，用户已登录 |
| O-T03 | 缺/错/过期 state 拒绝且平台调用 0 次 | 通过：三种情况均 403，`get_access_token_by_code` 未被调用 |
| O-T03b | 跨浏览器（不同 session）回调 | 通过：另一 client 请求 403，平台未被调用 |
| O-T04 | 重复回调拒绝；同渠道二次发起后旧 state 失效 | 通过：旧 state 403，新 state 成功一次后再回调 403 |
| O-T05 | 同邮箱已有本站账号不自动登录 | 通过：不建立登录态，创建 PendingBinding，邮件提示已有账号 |
| O-T05b | 同邮箱已有账号需先登录再确认 | 通过：未登录点链接 403 且不消费；登录该账号后 302 绑定成功 |
| O-T06 | 篡改 sign/换浏览器/错 id | 通过：均 403，binding.consumed 仍为 False，无关联写入 |
| O-T07 | 新邮箱经补邮箱表单一次绑定成功 | 通过：302，binding.consumed=True，OAuthUser.author 已挂载 |
| O-T07b | 同一 nonce 二次打开链接 | 通过：第二次 400 |
| O-T09 | 已绑定但 author is_active=False | 通过：403，不建立登录态 |
| 表单 | RequireEmailView 提交邮箱创建 PendingBinding 并发邮件 | 通过：302，邮件 outbox 含链接 |

## 本地整站验证

本轮在隔离 runner 内完成全部功能验证；真实浏览器渠道联调由组长 SZX 在统一本地版本上录制时完成。GZX 模块在 settings_demo 下的入口：

- 发起：`GET /oauth/oauthlogin?type=github&next_url=/`
- 回调：`GET /oauth/authorize?type=github&code=...&state=...`
- 补邮箱：`GET /oauth/requireemail/<oauthid>.html`
- 确认：邮件链接 `/oauth/emailconfirm/<id>/<sign>.html`
