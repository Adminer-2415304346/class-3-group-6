## 2. 方案与改动文件/符号

### D91 独立本地运行配置（`djangoblog/settings_demo.py`，94 行新增）

- `from .settings import *` 显式继承生产配置，再用同名变量覆盖，**不改 `djangoblog/settings.py`**；模块只在 `--settings=djangoblog.settings_demo` 时生效。
- `DEMO_MODE = True` 作为本地模式的唯一开关，诊断命令输出中回显该值。
- 目录规则：`DEMO_RUNTIME_DIR = BASE_DIR/demo_runtime`，下分 `db/ media/ whoosh/ logs/`，导入时按需创建；可用环境变量 `DJANGO_DEMO_RUNTIME_DIR` 整体改址。所有路径由 `BASE_DIR` 推导，不写死盘符。
- 数据库：`DATABASES['default']` 改为 `sqlite3`，文件 `demo_runtime/db/demo.sqlite3`，`OPTIONS={'timeout': 20}`。
- 媒体/索引：`MEDIA_ROOT=demo_runtime/media`；`HAYSTACK_CONNECTIONS['default']['PATH']=demo_runtime/whoosh`；`globals().pop('ELASTICSEARCH_DSL', None)` 明确移除继承的 ES 配置。
- 缓存/邮件：`CACHES['default']` 为 `LocMemCache`（`LOCATION='djangoblog-demo-locmem'`）；`EMAIL_BACKEND=console`，`EMAIL_HOST=127.0.0.1:1025`，凭据留空（口令位保留 `DJANGO_DEMO_EMAIL_PASSWORD` 环境变量入口，避免硬编码被扫描）。
- 静态/日志：`STORAGES` 用 `FileSystemStorage` + `StaticFilesStorage`（本地不跑 collectstatic，生产 `ManifestStaticFilesStorage` 保留在生产设置中）；`LOGGING` 深拷贝生产配置后把文件处理器改到 `demo_runtime/logs/djangoblog.log`。
- 其他：`DEBUG=True`（runserver 供静态）、`ALLOWED_HOSTS` 仅本机、`CSRF_TRUSTED_ORIGINS` 仅 8000 端口、`BAIDU_NOTIFY_URL`/`WXADMIN` 置空，避免演示时触发外部请求。

### D92 环境诊断（`djangoblog/demo_checks.py` 182 行 + `demo_healthcheck.py` 41 行）

- 检查集合 `CHECKS`：`check_database`（真实 `SELECT 1`）、`check_cache`（set/get/delete 往返并比对值）、`check_templates`（加载 `share_layout/base.html`）、`check_frontend_manifest`（manifest 存在/可解析/非空/逐条校验 `file`、`css` 产物存在，结构异常单独计为问题）、`check_media_directory`（存在/是目录/写探测文件后删除）。
- `run_checks()` 汇总为 `{status, demo_mode, settings_module, checks[]}`，每条 `{name, status, detail, fix}`；任一 failed 则整体 `failed`。
- 命令 `demo_healthcheck`：`--format=json|text`，`text` 打印 `status=… demo_mode=…` 与逐项 `[ok|failed] name: detail`，失败追加 `修复：…`；`status≠ok` 时 `raise SystemExit(1)`。
- 边界：不请求 SMTP/OAuth/微信/OpenAI/ES；不输出 `SECRET_KEY` 或连接凭据（有测试断言）；异常统一转成 failed 并保留异常类型，不吞异常后打印成功。

### 3.2 迁移、建号、启动

```powershell
.venv\Scripts\python manage.py migrate --settings=djangoblog.settings_demo
.venv\Scripts\python manage.py createsuperuser --settings=djangoblog.settings_demo
.venv\Scripts\python manage.py runserver 127.0.0.1:8000 --settings=djangoblog.settings_demo
```

- 入口：`http://127.0.0.1:8000/`（首页）、`/login/`（登录）、`/admin/`（后台）、`/health/`（探活）、文章 `http://127.0.0.1:8000/article/<年>/<月>/<日>/<id>.html`。
- 角色：`createsuperuser` 建的账号既是后台管理员也是前台作者，可发文章与评论。
- 本地样本：登录 `/admin/` 发一篇已发布文章（或 `python manage.py shell` 用 ORM 建 `Category`/`Tag`/`Article`），即可复现首页列表、文章详情与评论提交。
- 目录规则：`src/DjangoBlog/demo_runtime/{db,media,whoosh,logs}`；删掉 `demo_runtime/db` 后重新 `migrate` 即从零重建（**可重复启动**）。
- 本地邮件：控制台后端，邮件正文直接打印在 runserver 终端；不投递真实收件人（`证据/local-email-console.txt` 有 `SENT=1` 的实际输出）。

### 3.3 诊断命令、字段与常见失败

```powershell
.venv\Scripts\python manage.py demo_healthcheck --settings=djangoblog.settings_demo --format=text
.venv\Scripts\python manage.py demo_healthcheck --settings=djangoblog.settings_demo --format=json
```

| 字段 | 含义 |
| --- | --- |
| `status` | 全部检查通过为 `ok`，任一失败为 `failed`；进程退出码 0/1 与之对应 |
| `demo_mode` | 是否加载 `settings_demo`（`DEMO_MODE`） |
| `settings_module` | 当前 `DJANGO_SETTINGS_MODULE` |
| `checks[].name` | `database` / `cache` / `templates` / `frontend_manifest` / `media_directory` |
| `checks[].detail` | 实际探测结果；失败时为异常类型 + 消息（不含密钥） |
| `checks[].fix` | 可直接执行的修复命令或操作 |

| 常见失败 | 诊断输出 | 处理 |
| --- | --- | --- |
| 未迁移/数据库不可用 | `database: OperationalError …` | `migrate --settings=djangoblog.settings_demo` |
| 前端未构建 | `frontend_manifest: 缺少 …manifest.json` | `cd src/DjangoBlog/frontend; npm ci; npm run build` |
| manifest 坏 JSON 或产物缺失 | `无法解析` / `assets/main-*.js` 缺失 | 重跑 `npm run build`，不要手改 manifest |
| 媒体目录被占/无权限 | `media_directory: … 不可写` | 检查目录权限或改 `DJANGO_DEMO_RUNTIME_DIR` |
