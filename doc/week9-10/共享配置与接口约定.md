## 2. 配置入口（已提供）

源码：`src/DjangoBlog/djangoblog/maintenance_config.py`。

```python
from djangoblog.maintenance_config import get_maintenance_option

interval = get_maintenance_option("RESET_SEND_COOLDOWN_SECONDS")
```

`get_maintenance_option(name)` 返回一个有效值；`get_maintenance_options()` 返回全部设置的新字典。可在Django设置中用 `MAINTENANCE_OPTIONS = {"某键": 值}` 部分覆盖；未覆盖项使用下表默认值。读取时验证，未知键、非法类型和非正整数抛 `ImproperlyConfigured`。不缓存读取结果，`override_settings` 会生效。默认集合不可变，返回字典的修改不影响其他调用。

| 键 | 默认值 | 含义/使用方 |
| --- | --- | --- |
| RESET_CODE_TTL_SECONDS | 300 | 重置验证码有效期，YFY；成功重置后仍立即消费 |
| RESET_SEND_COOLDOWN_SECONDS | 60 | 同邮箱发送冷却，YFY |
| RESET_MAX_FAILURES | 5 | 同重置挑战连续错误上限，YFY |
| RESET_LOCK_SECONDS | 900 | 重置挑战锁定时长，YFY |
| COMMENT_MAX_LENGTH | 2000 | 去首尾空白后的评论字符上限，WZY |
| COMMENT_INTERVAL_SECONDS | 30 | 同用户成功评论的最小间隔，WZY |
| COMMENT_DUPLICATE_WINDOW_SECONDS | 120 | 同用户/文章/内容重复窗口，WZY |
| OAUTH_STATE_TTL_SECONDS | 300 | 授权state有效期，GZX |
| OAUTH_BIND_TTL_SECONDS | 600 | 待绑定邮箱证明有效期，GZX |
| ROBOT_SESSION_TTL_SECONDS | 900 | 管理员认证会话有效期，SY |
| ROBOT_CONFIRM_TTL_SECONDS | 60 | 单个命令确认票据有效期，SY |
| ROBOT_COMMAND_TIMEOUT_SECONDS | 10 | 允许命令的进程超时，SY |
| ROBOT_OUTPUT_MAX_CHARS | 4096 | 命令返回消息的字符上限，SY；不等同进程内存限制 |
| UPLOAD_MAX_BYTES | 5242880 | 单张图片5MiB上限，SZX |
| UPLOAD_MAX_PIXELS | 20000000 | 图片像素上限，SZX |
| UPLOAD_ALLOWED_FORMATS | JPEG、PNG、WEBP | Pillow识别格式允许列表，SZX |
| ROBOT_ALLOWED_ACTIONS | python_version | 唯一已约定可执行动作，SY |

格式/动作可用tuple或list覆盖，读取后为tuple，禁止重复和未知值。图片格式不能为空；空动作列表表示禁用全部命令。新增动作或配置键先由SZX修改本约定与读取入口。成员不要另加硬编码阈值；测试和视频可临时覆盖时长，但须说明。

## 3. HTTP与前端响应

新改造的JSON接口（验证码发送、图片上传）统一返回：

```json
{"success": true, "code": "sent", "message": "验证码已发送", "data": {}, "retry_after": 60}
```

- 固定键：`success`布尔、`code`稳定小写标识、`message`可展示文本、`data`对象。`retry_after`按需出现，值为非负整数秒。
- HTTP：成功200；格式/内容错误400；无权限403；不存在404；方法错误405；请求过频429（同时返回`Retry-After`）；投递等可恢复依赖故障503。CSRF失败沿用Django的403页面，不强改全站中间件。
- 表单提交沿用原HTML表单错误/重定向契约，限频和内容错误用表单错误回显；不要把整个站点改成JSON。OAuth的拒绝页与安全重定向沿用HTML。
- YFY同时修改`launcherAccount.js`解析JSON；成功倒计时以服务端秒数为准；429展示剩余时间。原注册、登录、找回密码表单行为继续回归。

### 3.1 YFY验证码接口

保留URL名称`account:forget_password_code`和POST字段`email`。成功`code=sent`，限频`rate_limited`，输入错误`invalid_email`，投递失败`delivery_unavailable`。申请接口不新增“邮箱是否注册”的差别提示。密码重置仍由原表单完成，不改URL名称。

### 3.2 SZX上传接口

保留`blog:upload`名称；仅POST，字段`file`，一次一张。仅有效且已登录的staff可上传，必须通过CSRF。旧固定签名不能代替权限。成功`code=uploaded`，`data`含`url/name/size/format`；错误码为`invalid_file/file_too_large/permission_denied`等。只接受实际解码通过且格式允许的图片，生成UUID文件名，保存到媒体存储并返回MEDIA_URL下的URL；不使用客户端路径。GCY演示配置负责独立MEDIA_ROOT，媒体路由由SZX统一接入。

## 4. 缓存、计时、验证与持久化

- 键前缀固定`week910:<app>:<purpose>:<sha256标识>`；邮箱、会话凭据等不用明文作为缓存键或日志。邮箱统一`strip().casefold()`，以本轮业务约定保持收发/验证一致。
- 各App只清理自己新增的键，不能用`cache.clear()`解除本人限频，也不能删除其他App的状态。
- 冷却/锁定至少保存到期时间，向前端返回真实剩余秒数；过期边界为`now >= expires_at`。测试使用可控时钟，不通过长时间sleep采证。
- Django缓存计数原子性取决于后端。本地LocMem验证只覆盖本进程，不能据此宣称多机限流已经验证。要求严格一次消费的OAuth绑定/命令票据采用数据库条件更新/唯一约束等可核实方案，并记录事务边界。
- 邮件发信仍调用`djangoblog.utils.send_email`，共享`send_email_signal`职责不变。验证码/评论限频的预留在操作失败或事务回滚后可重试，避免把失败写入永久当作成功操作。

## 5. OAuth与accounts边界

GZX负责`oauthlogin/authorize/RequireEmailView/emailconfirm`和平台管理器。YFY负责本地注册/激活/密码重置，二者签名purpose/salt分别使用`week910.oauth.bind`与`week910.accounts.activate`，不可互认。

1. state由服务端生成不可预测值，按渠道保存在当前浏览器会话，包含发起时间和已校验next地址；回调先校验渠道、时效、state再调用平台。每渠道仅最新一次有效，不同渠道分开保存；无效回调不调用换token接口，成功消费后重复回调拒绝。
2. `get_authorization_url`保留原位置参数的兼容调用，并扩展关键字`state`。外发state作为独立OAuth参数；callback URL使用配置值，next地址存会话，回调不再采信任意传入next。
3. 已绑定的本站用户必须`is_active=True`才可登录。未绑定的第三方邮箱不能直接让请求者取得同邮箱本地账号；对新绑定统一走待绑定证明。
4. 待绑定记录绑定`oauth_user_id/email/随机nonce/浏览器上下文/期限/消费状态`。浏览器上下文用会话中的随机标识，避免直接绑session_key导致本地login轮换会话后失效。修改隐藏ID、邮箱、nonce、浏览器或过期/已消费请求必须拒绝。
5. 邮箱证明建议用TimestampSigner/JSON签名，但时间签名不提供一次性消费；另行验证服务端待绑定记录。已有同邮箱本地账号时要求先登录该有效账号再显式确认绑定；确认过程保留原会话上下文。新邮箱创建用户前完成本流程验证。
6. GZX可在oauth内新增绑定模型/迁移；YFY本轮不改BlogUser邮箱唯一约束或替GZX实现OAuth。账号冲突和新建路径分别测试，旧无期限绑定链接失效并提示重新发起。

## 6. WZY与blog缓存边界

`Article.comment_list()`继续返回QuerySet；`Comment.get_reactions_summary(user=None)`的现有结构及单次读取预算保持。继续使用`blog.comment_cache.invalidate_comment_caches(article_ids, using=...)`，其提交后失效语义不变。

限频/重复判断须在内容、文章和父评论校验通过后进入。文章关闭、草稿、无效父ID、事务回滚或保存失败不计成功评论；重复检测包含用户、文章、规范化正文和回复目标。表情切换不套用评论发布的30秒冷却。评论缓存接口不发邮件，通知仍按既有提交后逻辑执行。

## 7. SY命令与会话边界

- `CommandHandler.run(title)`保留入口。现有`commands.command`改填动作ID，例如`python_version`；动作在servermanager内部固定注册为`[sys.executable, "--version"]`。同时受`ROBOT_ALLOWED_ACTIONS`限制，不把数据库文本当shell命令或任意argv执行。旧shell文本在管理员迁移配置前明确拒绝执行。
- 使用`shell=False`和固定可执行程序/参数，禁止以`cmd /c`、PowerShell或批处理包装重新引入shell解析。帮助信息只列可用动作。
- 管理员会话有认证期限；每次待执行命令生成票据，绑定用户、动作、创建/过期和消费状态。Y只能消费当前未过期票据，exit取消；重新认证不复活旧票据。并发消费用可核实的持久化条件写入，不能把会话“先读再删”描述为跨进程原子保证。
- 未授权/已过期/重复确认都不得调用执行器；超时/非零退出/输出截断有明确返回。测试mock执行器；本地视频可演示固定`python_version`，微信/OpenAI替身须标明。
